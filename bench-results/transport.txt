================================================================================
  VynaHL7 Transport Benchmark Report
================================================================================

  1. PURPOSE
  ----------
  Measure end-to-end HL7 message processing throughput and latency over real
  network transports (MLLP over TCP, HTTP/1.1) on localhost. This benchmark
  answers: "How fast can VynaHL7 send, receive, parse, and acknowledge HL7 messages
  over a network?" — the metric that matters in production interface engines.

  The full round-trip includes:
    Client: encode message → MLLP/HTTP frame → TCP send
    Server: TCP receive → deframe → parse HL7 → generate ACK → frame → TCP send
    Client: TCP receive → deframe → parse ACK → return

  Test methodology follows standard HL7 interface engine benchmarking practices
  (T1 store-and-forward, T2 translation, T3 round-trip). Both client and server
  are VynaHL7's own MLLP/HTTP implementations running on localhost.

  2. METHODOLOGY
  ---------------
  Transport:     MLLP/TCP (intra-org, persistent connection, VT/FS/CR framing)
                 HTTP/1.1 (inter-org, reqwest client, axum server, keep-alive)
  Network:       localhost (127.0.0.1), auto-allocated ephemeral port
  Server:        VynaHL7 MllpServer / HttpServer with ACK handler
  Messages:      3 types — ADT^A01 (admission), ORU^R01 (lab result), RDE^O11 (Rx)
  Concurrency:   1, 4, 8 simultaneous clients (persistent connections)
  Warmup:        1,000 messages discarded before measurement
  Iterations:    10,000 (single), 20,000 (4c), 40,000 (8c) measured round-trips
  Sustained:     15-second continuous send (single client, ADT^A01)
  Timing:        std::time::Instant per round-trip; sorted for percentile analysis
  Latency:       Wall-clock time from send_message() call to ACK received
  Throughput:    iterations / total_wall_clock_time (includes all overhead)
