**内存显微镜：HL7 解析器的内存分配剖析**

我们编写了一个自定义内存分配器，精确统计解析 HL7 消息时的每一次堆分配——这不是 VynaHL7 本身的功能，而是基准测试工具中的测量技术。

Rust 的 GlobalAlloc trait 允许你临时用自己的实现替换系统分配器——只需实现一个 trait，进程中的每一次堆分配都会经过你的代码。我们利用这一特性构建了一个 CountingAllocator，它封装标准分配器并记录每一次 alloc() 调用。在 Java 或 C# 中，垃圾回收器掌管堆内存，因此无法获得这种分配级别的可见性。

核心指标："放大系数"——堆分配字节数除以输入字节数。

| 消息类型 | 输入大小 | 堆分配 | 放大系数 |
|---------|---------|--------|---------|
| MDM^T02（文档） | 2,627B | 38KB | 14.6x |
| SIU^S12（排程） | 729B | 34KB | 46.2x |
| ADT^A01（入院） | 959B | 58KB | 60.1x |
| 生产环境脏数据 | 342B | 42KB | 122.0x |

最大的消息（MDM 文档）反而放大系数最低。长文本块意味着更少的结构性分配。而那条 342 字节的"脏"消息——充满空字段和尾部分隔符——放大系数最高，因为每个分隔符位置都会创建一个结构体。

分配次数直接驱动解析时间。这些数据精确指引了我们的优化方向。
